## 0. Протокол сесій — кодові фрази

Одні й ті самі фрази в чаті і в Claude Code.

**`/старт`** — Дмитро пише: дату, день тижня, час, скільки є часу (напр. «/старт 15.09.2026, вт, 22:10, 40 хв»).
Claude у відповідь, ДО будь-якої роботи:
1. читає цей файл (у чаті — з knowledge; у Claude Code — з репо) і не спирається на пам'ять розмови;
2. звіряє всі дати від названої дати (день тижня рахує, не згадує);
3. відповідає трьома рядками: де ми (останнє зроблене) · що робимо зараз (одна задача) · що потрібно від Дмитра.
Жодних довгих вступів, жодних «нагадаю контекст» на пів екрана.

**`/фініш`** — Claude віддає:
1. рішення сесії (3–7 рядків);
2. оновлений блок для цього файлу (розділи 3–4) — готовим текстом;
3. ТЗ для Claude Code, якщо в сесії з'явилось;
4. одна фраза: що наступне і коли.
У Claude Code `/фініш` додатково означає: оновити CLAUDE.md і docs/план.md, закомітити, запушити (тільки після підтвердження).

**`/дата`** — швидка перевірка: Claude називає сьогоднішню дату, день тижня і три найближчі публікації з датами. Використовувати, коли є сумнів.

**`/стоп`** — Дмитро зупиняє Claude посеред відповіді: щось не так (дата, факт, «не те»). Claude не виправляє наосліп — питає, що саме, збирає повний список, переробляє один раз.

- Між постами одного автора — мінімум 24 години.

- Рубрики (за 2 тижні проходять усі): кейси з цифрами · біль клієнта · ринкова аналітика · ветеранський найм · процес зсередини.
- Пост ставиться в рідне планування LinkedIn не пізніше ніж за добу до виходу.

## 2. Одиниця контенту — що вважається «готовим постом»

Пост без цього — не дописаний:
- текст поста (800–1500 знаків, гачок у першому рядку, одне питання в кінці);
- список, хто коментує (3–4 людини);
- текст кожного коментаря — різний, змістовний, не «🔥»;
- час кожного коментаря (розтягнуто в першу годину: напр. +15, +40, +90 хв);
- відповіді Олени на кожен коментар (продовження розмови, не «дякую»).

Правила текстів: жодних вигаданих фактів, цифр, кейсів — тільки реальне або позначка `[...]`; голос Олени — за `context/портрет-голосу-олени.md`; без «ШІшності» і мотиваційної води; зовнішні посилання в тілі поста заборонені.

## 5. Рішення по SMM Ops (незмінні)

1. Новий окремий сервер Hetzner (CX22, Helsinki, Ubuntu 24.04). Старий сервер (Threat Monitor, wa-bot) не чіпаємо взагалі.
2. Стек: Node/Express + better-sqlite3 + grammY + node-cron, одна HTML-сторінка без фреймворків, pm2, nginx. Репо `Hell-in-Star/smm-ops`. Домен `smm.wtf-alerts.com`.
3. Модулі по черзі: 1 календар зі статусами · 2 люди і прогрів (бот) · 3 нагадування · 4 метрики (ручна форма) · 5 тижневий зріз у /context · 6 збирач новин у /context (скрипт збирає і фільтрує, Claude інтерпретує). Публікація через API — етап Д: профіль Олени (самообслуговування, w_member_social) → FB/IG → Threads; сторінка LinkedIn — тільки нагадування, поки немає партнерського доступу.
4. Підключення людей до бота — персональним посиланням з кодом (`t.me/<бот>?start=<код>`), ніки й номери не потрібні. Бот не може писати першим — людина тисне Старт.
5. Коментарі: у кожного — власний час (зсув від публікації або абсолютний), бот шле за 5 хв до нього (в налаштуваннях): пряме посилання на пост + текст коментаря окремим повідомленням + час + кнопка «Готово». Шаблон часів за замовчуванням, правиться руками.
6. Токен LinkedIn живе 60 днів — система попереджає за 14 днів до протухання.
7. Гілки чату: ця (SMM Ops / стратегія / план) · «Контент» — нова на кожну пачку · Claude Code — виробництво.
