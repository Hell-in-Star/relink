# Автоматизація і контент-конвеєр ReLink

> Призначення файлу: точка входу для окремої гілки чату «Автоматизація + контент-конвеєр»
> у браузерному проєкті ReLink. Тут зафіксовані всі рішення, ухвалені в гілці Facebook-стратегії
> (серпень 2026), щоб нова гілка стартувала без втрати контексту.
> Місце в репо: `context/автоматизація.md`.

## Навіщо це все (вводні Дмитра)

- Дмитро працює над усім SMM ReLink сам, з обмеженим часом і нестабільним зв'язком.
  Автоматизація — не «зручність», а умова виживання проєкту.
- Окремої людини для створення контенту немає і не буде. Дизайнерської експертизи в команді немає:
  Дмитро може оцінити креатив лише «подобається / ні».
- Скоуп: усі чотири мережі (LinkedIn — стратегія вже є; Facebook — у роботі; Instagram і Threads — попереду).
- Прицільна мета: налагоджена система має бути придатною до повторного використання
  на інших клієнтських проєктах Дмитра в майбутньому.

## Урок, який не можна забувати

PDF-презентацію робили дизайном у коді (HTML → рендер → подивитись → правити). Це спалило
всі токени підписки Max 5x, результат нікому особливо не сподобався, брендбук лишився недоробленим.
**Висновок: дизайн у коді ітераціями — заборонений метод для потокового контенту.**
Він лишається тільки для разових складних речей. Для потоку — тільки шаблонний підхід (Canva).

## Ухвалені рішення

### 1. Графіка — Canva (НЕ Figma)

- Figma відхилена: інструмент для дизайнерів, що малюють з нуля; без дизайнерського ока не працює.
- Canva — конструктор «наповнюй, не малюй»: тисячі готових шаблонів від професійних дизайнерів.
  Проблема «можу сказати лише подобається/ні» зникає: вибір з готових професійних шаблонів —
  це і є вся потрібна експертиза. Обраний шаблон фіксується, далі в нього лише підставляються тексти.
- Brand Kit (тільки в тарифі Pro): один раз завантажуються шрифти ReLink (Geologica, Onest),
  палітра і лого — всі шаблони автоматично в бренді.
- **Canva має офіційний конектор для Claude** (через MCP): Claude може створювати, автозаповнювати
  і експортувати дизайни прямо з чату. Цикл: Дмитро один раз затверджує шаблони → Claude наповнює
  їх текстами пачкою → Дмитро дивиться готове і каже «ок/замінити». Без Claude Code, без токенів на рендери.
  Відоме обмеження: конектор буває нестабільним (таймаути), якість залежить від чіткості інструкцій
  (розмір, бренд-елементи, тексти, обмеження задавати явно) — інструкції пише Claude.
- **Економіка:** пілот — 0 грн (безкоштовний тариф + місяць Pro новим акаунтам).
  Робочий режим — Canva Pro: $15/міс офіційно; для України річна підписка 5200 грн/рік (~433 грн/міс).
  Якщо після пілота «так» — брати одразу річну. Сірі схеми (складчини, VPN-ціни) — НЕ використовувати:
  втрата акаунта = втрата всієї фабрики шаблонів.
- Токени/ліміти Canva: на основну роботу (шаблони, підстановка, експорт) лімітів НЕМАЄ — фікс-ціна.
  Кредити витрачаються лише на вбудовані AI-генерації (картинка/відео з нуля) — у нашому конвеєрі
  це рідкісні разові випадки, місячного ліміту Pro вистачає.
- Плановий обсяг: ~15–25 графічних постів + 4–8 Reels на місяць на всі 4 мережі
  (з урахуванням крос-постингу). Для Canva це мізер — запас багатократний.

### 2. Відео — три рівні

1. **Конвеєрний (основа, ~80% відео):** шаблонні Reels у Canva — сток + текст + музика.
   Ніхто не знімається. Покрито тим самим тарифом Pro.
2. **Живий (ростить довіру):** Олена погано знімає відео — тому вимога знижена з «знімайся»
   до «надішли сирі кадри з телефону» (офіс, зустріч, процес; 15–20 сек без слів; раз на місяць).
   Схема авто-монтажу: сценарій пише Claude ДО зйомки (список конкретних кадрів) → кадри летять
   Дмитру → збірка у фірмовому відео-шаблоні Canva (титульний екран → «кишені» під кадри →
   фінал з лого → фірмові субтитри → музика з бібліотеки). Збірка одного відео = 10–15 хв
   механічної роботи. Голос: голосове повідомлення Олени поверх кадрів або закадровий текст.
   Субтитри: текст зі сценарію, або авто-розпізнавання (Canva/CapCut) — якість українською
   перевірити на пілоті, не обіцяна.
3. **AI-генератори відео (Veo 3.1, Kling 3.0 тощо):** НЕ входять у робочу систему. Це резерв
   на випадок кадру, якого немає ні в стоку, ні в реальності. Sora закривається (API — вересень 2026).
   Червона лінія назавжди: жодних згенерованих «людей компанії» — для бізнесу на довірі
   фейкові обличчя (включно з аватарами HeyGen/Synthesia) — репутаційна міна.

### 3. Планувальник — одне вікно на всі мережі

- Meta Business Suite (безкоштовний): постинг FB+IG, спільна скринька повідомлень, автовідповіді
  в Messenger. Не покриває LinkedIn і Threads.
- Для всіх чотирьох мереж: Metricool або Buffer (обидва ведуть FB, IG, LinkedIn, Threads з одного
  календаря, мають безкоштовні/дешеві тарифи). Вибір — тестом на етапі запуску, рішення на 15 хвилин.
- Додатковий обов'язковий критерій вибору: можливість одним кліком поставити на паузу всі
  заплановані пости одразу — потрібно для протоколу реагування на резонансні події (п. 7 нижче;
  правила — `smm/стратегія-загальна.md`, розділ 8).

### 4. Бот-оркестратор прогріву (власна розробка на Hetzner)

Бачення Дмитра, підтверджене як реалізовне. Це НЕ планувальник (планувальник лише публікує пости) —
це шар оркестрації людей ПІСЛЯ виходу поста:

- Джерело правди: контент-календар (спільна таблиця): дата, мережа, пост, хто коментує,
  заготовлений текст коментаря.
- Пост виходить через планувальник → бот бачить час публікації → шле кожному задіяному
  співробітнику в Telegram: посилання на пост + його персональний коментар + нагадування
  через N годин, якщо не виконано → кнопка «Готово» → статус лягає в календар →
  Дмитру щоденний дайджест («5/6 виконали, Олена — ні»).
- Це матриця прогріву з LinkedIn-стратегії, поставлена на рейки; масштабується на FB/IG/Threads
  без переробки (мережа — колонка в календарі).
- Відкрите технічне питання: прямий лінк на пост не існує наперед — він з'являється після публікації.
  Варіанти: (а) постинг через планувальник з API, звідки бот сам забирає URL опублікованого поста;
  (б) MVP: бот шле лінк на сторінку/профіль + текст коментаря (один зайвий клік людині).
  Вирішується на етапі ТЗ бота.

### 5. Контент-план і контент-календар: дворівнева схема

Один узагальнений контур на всі чотири мережі, два рівні:

1. **Контент-план (стратегічний, оновлюється щомісяця)** — файл `context/контент-план.md` у репо:
   теми і акценти місяця, рубрики по мережах, оффер/кампанії місяця, що знімає Олена.
   Лежить саме в /context, щоб синхронізуватись у knowledge браузерного проєкту — Claude бачить
   актуальний план у будь-якій гілці і генерує тексти пачками за ним. Цикл: останній тиждень
   місяця — ревізія (що спрацювало → теми наступного) → Claude Code оновлює файл → пуш →
   синхронізація knowledge. Історія версій — у git.
2. **Контент-календар (операційний, живе щодня)** — Google-таблиця. Рядок = одиниця контенту:
   дата, мережа, рубрика, текст/лінк на креатив, статус (чернетка → затверджено → заплановано →
   опубліковано), хто коментує, текст коментаря. Чому таблиця: це джерело правди для
   бота-оркестратора (п. 4); Олена і Надя працюють з телефона без git; статуси міняються щодня.

Зв'язка в цикл — з двоступеневим погодженням замовником (домовленість Дмитра):

1. **~20 число** — ревізія місяця (що спрацювало) → чернетка плану і скелета календаря
   наступного місяця (дати, мережі, рубрики, теми, оффер).
2. **20–25 число** — план + календар на погодження замовнику. Правки збираються списком,
   вносяться одним заходом.
3. **До кінця місяця** — генерація першої пачки текстів і креативів за затвердженим планом →
   окреме погодження замовником (пачкою, не поштучно) → планувальник.
4. **Протягом місяця** — друга пачка (середина місяця) тим самим циклом: тексти/креативи →
   погодження → планувальник; публікація за розкладом; бот-оркестратор веде прогрів по таблиці.
5. **Кінець місяця** — факти з таблиці → щомісячний звіт замовнику → ревізія наступного плану
   (цикл замикається).

Статуси одиниці контенту в таблиці: чернетка → на погодженні → затверджено замовником →
заплановано → опубліковано.
Формула: план каже «що і чому», календар — «що, коли, де і в якому статусі»;
замовник погоджує двічі — спершу план місяця, потім тексти й креативи пачками.

Перший контент-план (вересень 2026) створюється разом зі спринтом Facebook, після готовності
стратегії Instagram — щоб одразу покривав усі активні мережі.

### 6. Лід-конвеєр (на етапі запуску реклами)

Ліди з Lead Ads не повинні лежати в рекламному кабінеті (відповідь у перші 5 хвилин кратно
підвищує шанс контакту; дзвінок через 30+ хвилин обвалює ймовірність угоди).
Схема: скрипт на Hetzner забирає ліди через API Meta → Google-таблиця (міні-CRM першого етапу:
лід, джерело, статус, відповідальний) → миттєве сповіщення в Telegram Дмитру і B2B-менеджеру.
Один конвеєр на всі мережі. Повноцінна власна CRM — тільки коли потік стабільний і таблиця
перестане справлятись (не будувати CRM на старті — пастка).

### 7. Скаут-бот резонансних подій (крайзис-протокол)

Той самий патерн, що скаут-бот Threads: скрипт на Hetzner моніторить офіційні Telegram-канали
тривог і зведень (Повітряні сили ЗСУ, ДСНС, обласні адміністрації) та ключові слова в новинних
стрічках (масовано, жертви, день жалоби). При спрацюванні — миттєвий сигнал у Telegram Дмитру
і Наді з коротким описом ситуації і питанням, чи ставити на паузу заплановані пости й рекламу
(кнопки — та сама механіка, що в боті-оркестраторі, п. 4).

Автоматизується тільки виявлення сигналу — рішення про паузу завжди ухвалює людина, той самий
принцип, що і в скаут-боті Threads («шукає бот, відповідає людина»). Рівні подій, дії і хто
відповідає — `smm/стратегія-загальна.md`, розділ 8.

Запобіжник: якщо 2+ години немає реакції ні від Дмитра, ні від Наді — планувальник ставиться
на паузу автоматично (безпечніший дефолт, ніж бездіяльність); активні рекламні кампанії
паузяться тільки вручну.

### 8. Рівні підключення Claude до системи

1. **Конектори в браузерному чаті** (вже зараз): Canva — перший; далі можливі планувальники.
2. **Автономні сесії Claude Code за розкладом** (вже практикується — нічні сесії):
   регулярні задачі в межах підписки, напр. «щопонеділка зібрати статистику мереж у звіт».
3. **Claude API + Telegram-бот на Hetzner** («написати боту з телефону — отримати пости де завгодно»):
   ВАЖЛИВО: API оплачується ОКРЕМО від підписки Max, живі гроші за кожен запит.
   Будується не зараз, а коли система запрацює і з'являться проєкти, які його окуплять.

Принцип розподілу: підписка Max — на мислення (стратегія, тексти, ТЗ); Canva — на картинки;
скрипти на Hetzner — на рутину; API — тільки коли рахується економіка.

## Сумісність з рештою проєкту

- Контент-буфер на 2 тижні і асинхронність — базові вимоги (специфіка доступності Дмитра).
- Все, що має пам'ятатись між сесіями — у файлах репо, не в переписці.
- Надя читає ці файли зі свого акаунта — писати зрозуміло для людини.
